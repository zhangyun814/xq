# 翻倍信号筛选

从知识星球语料里提炼「翻倍」这类说法的买入信号，用历史行情验证它到底赚不赚钱，再把结论做成一个点按钮就能跑的筛选台。

核心结论：**「翻倍」这个词必须拆开看**。语料里它 54% 指业绩翻倍、24% 才指目标价，两者的股价含义几乎相反。只有目标价那一层站得住，且窗口在 20 个交易日，不是 5 天。

---

## 结论摘要

| 口径 | N | T+20 超额均值 | 中位 | 胜率 | t 值 |
|---|---|---|---|---|---|
| **目标价翻倍** | 46 | **+11.28%** | +3.53% | 54.3% | **2.67** |
| 业绩翻倍 | 91 | −1.44% | −1.96% | 41.8% | — |
| 模糊 | 32 | +6.43% | +7.61% | 59.4% | — |

**买入**：信号次日开盘买入，不挂回调单、不等均线。11 种时点里次日买入是唯一全胜解（100% 成交、+12.14%）。等 −3% 回调的条件收益 +12.52% 看着更高，但只买到 51.1% 的单子，整体掉到 +6.40%；等 −8% 的条件收益是 **−3.18%**——愿意深跌才买的，买到的都是坏消息。

**卖出**：不设止损。21 种出场规则里 9 个带价格触发的全部更差。入场后最大浮亏中位就是 −10%，8% 止损会打掉 57.8% 的仓位，而收益高度依赖右尾（最大浮盈均值 +31.7%）。机械出场就「止盈 +10% 或持满 20 个交易日，先到先出」。

## 快速开始

**日常只有一条命令，25 秒。**

```bash
python3 active_signals.py          # 抓新帖 + 实时行情 + 重算，出结果和 CSV
```

结果打印在终端，同时写出 `out/活跃池_近5天翻倍.csv`，并在 `out/归档/` 下按日期留一份（如 `活跃池_近5天翻倍_2026-10-19.csv`），历史逐次可查。这条命令是**只读**的——除了 `out/` 里的产物，不改动任何底稿。

**必须在有语料的那个目录里跑。** `resolved.json` / `klines.json` 被 gitignore 挡掉了，换一个目录（比如刚 clone 下来的仓库）跑，就没有历史语料——活跃池会从 1,500 多只掉到 900 只上下，结果是假的「0 只」。现在这种情况会明确打警告，不再静默：

```
!! 没有 resolved.json：无历史语料，活跃池只能覆盖近 5 天
   先跑 python3 run_all.py --full 建语料库（约 3 分钟），再回来筛
```

### 什么时候该重算底稿（加 `--full`）

上面那条命令用的是**已有的**历史语料和日线。它们不需要天天刷新，原因有三个：

1. **重算出来的数几乎不动。** 事件研究统计 1,200+ 个历史事件，每天多几十条新帖对中位数的影响在小数点后两位。你多等 2 分半，未必看得出差别。
2. **代价不对称。** 日常 25 秒，`--full` 约 3 分钟，还要额外发一次全市场行情请求。
3. **默认值必须朝安全侧。** 日常筛选只读；`--full` 会改写 `resolved.json`、`klines.json`、`summary.json`。把写操作设成默认，等于每次看盘都在动底稿，中途失败会留下「语料更新了、日线没更新」的半更新状态，下次看盘还当它是新的。

所以判断标准是一句话：**日常是读数，`--full` 是对时。** 只有钟明显跑偏时才需要对时。

| 情况 | 为什么值得跑 |
|---|---|
| 隔了半个月以上没跑 | 攒下数百条新帖，样本开始有意义地移动 |
| 月底复盘「这套说法还灵吗」 | 想看胜率、t 值有没有漂移 |
| 改过 `semantics.py`、关键词或口径 | 改了不重算，等于白改 |
| 要把 `report.html` 给别人看 | 里面的数字得是当周的 |

```bash
python3 active_signals.py --full       # 约 3 分钟
```

它内部就是替你跑一遍 `run_all.py`：抓帖 → `resolve_v2.py` 合并语料 → `fetch_klines.py` 补日线 → `event_study.py` 重跑事件研究 → 再筛一遍。

**刷新失败不会中断筛选**，会打一行 `!! 底稿刷新失败，继续用现有语料筛选` 然后照常出结果。好处是永远有结果，坏处是你可能没注意到手里的其实是旧底稿——跑完扫一眼有没有这行。

> 想一次补更多历史帖（比如新换机器），直接 `python3 run_all.py --full`，它会把抓帖窗口从 7 天提到 30 天。`active_signals.py --full` 内部调用的是不带参数的 `run_all.py`，只抓 7 天。

### 不用管的：`build_universe.py`

它负责建股票名录（代码 ↔ 名称 ↔ 行情符号），产物是 `universe.json` / `alias.json`。由 `resolve_v2.py` 在检测到这两个文件缺失时**自动调用**，你不需要手动跑。名录一年才变几次（新股上市、更名、退市），不存在「每天要更新」的问题。

### 三条命令的关系

不是三选一，是两层调用：

```
active_signals.py            你唯一要记的入口
├─ 日常：抓帖 → 合并语料 → 用现成日线算浮盈 → 出 CSV
└─ --full 时先转交：
   run_all.py                刷新底稿
   └─ resolve_v2.py  ──→ 名录缺失时自动调 build_universe.py
```

**全部是 Python 标准库**，无第三方包。外部只依赖两个东西：

## 语义消歧怎么做的

同一句「翻倍」可以是三种意思，必须先分清：

```
"净利同比翻倍"        → 业绩（已发生，通常早被 price in）
"至少翻倍以上空间"    → 目标价（卖方在给未来位置）
"今年第三只翻倍股"    → 称谓（复盘，无预测含义）
"翻倍增长可期"        → 模糊
```

判定方法：看信号词前后 ±18/22 字内，**股价类词**（空间/股价/目标价/市值/弹性/涨幅/上行/赔率/上看/至少）和**业绩类词**（净利/扣非/归母/营收/收入/毛利/同比/环比/增长/指引/出货/订单…）谁离得更近。

另外有一条**过去时过滤**：窗口里出现「已、接近、年内、累计、涨幅达」这类词，且没有「有望、目标、空间、将、预计」时，判为业绩。这条规则是为了修掉「药明康德年内股价已接近翻倍」被误判成目标价——那句话在复述涨幅，不是给目标价。

## 踩过的坑

**开/收必须同源。** 首版混用新浪不复权收盘 + 腾讯前复权开盘，算出 −31.7% 的隔夜缺口和 +42.7% 的日内涨幅，数字荒谬到一眼假（688623 前收 93.25、开 63.65、收 90.83）。改成两个价格都取腾讯前复权后，缺口回到 +2.49%、中位 +0.13%，合理。

**「等回调」是幸存者偏差。** 只看成交样本，等 −3% 回调的收益比直接买还高。必须同时报「条件收益」（只算买到的）和「整体收益」（买不到记 0），才能看出真相。

**发帖时间决定可行性。** 60%+ 的帖子发在 21–23 点，当日收盘买入根本不可能，最早的下手时点是次日开盘。

**语义规则改一处，全表数字都要重跑。** 加过去时过滤后，目标价口径从 47 掉到 46，t 值从 2.62 变 2.67，业绩口径从 82 涨到 91。改完 `semantics.py` 必须重跑 `event_study` → `exit_rules` → `entry_rules` → `report.html`，不能只改一处。

**写语料的脚本必须用合并，不能覆盖。** `resolved.json` 里的历史语料是从 `raw/` + `samples/` 解出来的，而这两个目录是可以清理的。清理之后，如果 `resolve_v2.py` 还按「扫描到的全部重写一遍」来干，它只会扫到这次抓的几页新帖，然后把 5,214 条历史**全部覆盖掉**。所以现在改成按 `topic_id` 合并：读旧文件当底，新解析的覆盖同名条目，其余原样保留。同理，`run_all.py` 原来的自建分页逻辑（`raw/inc_*.json` + `state.json` 游标）已经删掉，统一走 `scan.fetch_posts`——**同一件事只留一条实现路径**。

## 口径边界

- 样本期 2025-08 ~ 2026-10，**单边偏强市**，熊市未验证
- 未计交易成本、滑点、涨跌停约束
- t 值未做多重比较校正（11 个分组同时检验，Bonferroni 阈值约 2.8），**属方向性参考，不是可以下重手的依据**
- N=46 不大，个别极端值对均值影响明显，中位数更可靠

这个项目能回答「这类说法历史上赚不赚钱」，不能回答「明天该买什么」。
